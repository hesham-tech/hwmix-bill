# طباعة ملصقات P2_3083 من HWNiX Bill

الربط يستخدم TiMini-Print Community CLI v0.9 على كمبيوتر Windows المتصل بالطابعة. لا يلزم تثبيت تعريف طابعة في Windows. لا يعمل تشغيل الخدمة على خادم الإنترنت بدل الكمبيوتر المحلي.

للتوزيع على المستخدمين استخدم المثبت 1.1.3 وراجع [دليل الإصدار](./DESKTOP_RELEASE.md). خطوات Node أدناه للمطور الذي يريد تشغيل الخدمة يدويًا.

## الإعداد اليدوي للمطور

تحتاج Node.js 20 أو أحدث. من جذر المشروع:

```powershell
npm run printer:setup
npm run printer:bridge
```

الإعداد ينزّل ملف CLI الرسمي من GitHub ويتحقق من SHA256، ويولّد رمز ربط خاصًا بهذا الكمبيوتر. لا ترفع `config.local.json` أو الملف التنفيذي إلى Git.

إذا كان لديك الملف التنفيذي بالفعل:

```powershell
npm run printer:setup -- --cli "D:\path\TiMini-Print-Command-Line-Windows-x86_64.exe"
```

للسماح للموقع الفعلي أو منفذ تطوير مختلف، استخدم عنوان الموقع من شريط المتصفح، دون مسار أو شرطة مائلة أخيرة:

```powershell
npm run printer:setup -- --origin https://billing.example.com
```

أعد تشغيل الخدمة بعد تعديل الإعداد. تعمل فقط على `127.0.0.1:19191`. يمكنك تشغيلها بالنقر مرتين على `start.cmd` وإبقاء نافذتها مفتوحة. لا تحتاج صلاحيات مسؤول أو فتح المنفذ للشبكة. لم يُضف تشغيل تلقائي مع Windows.

## الاستخدام

1. أغلق/افصل اتصال TiMini GUI وتطبيق الهاتف؛ قد تحتكر الطابعة اتصال Bluetooth واحدًا.
2. افتح طباعة الملصقات من المنتج أو أصناف الفاتورة في المشروع.
3. اختر «طابعة Bluetooth عبر TiMini»، وأدخل رمز الربط الظاهر في نافذة الخدمة.
4. المقاس الحالي 50×60 مم. اختر نوع الورق الفعلي: ملصقات بفواصل، رول مستمر، أو علامة سوداء.
5. اضغط «فحص خدمة الطباعة» لحفظ الإعداد والتحقق من الخدمة والملف التنفيذي. هذا الفحص لا يختبر اتصال الطابعة.
6. راجع المعاينة، وابدأ بملصق واحد. اسمح لـChrome بالوصول المحلي عند طلبه.

عند اختيار «طباعة المتصفح» يبقى مسار نافذة الطباعة المعتادة متاحًا. الإعداد محفوظ في المتصفح وعلى الجهاز، ولا يحتوي بيانات حسابك أو كلمات مرور المشروع. رمز الربط يتيح الطباعة محليًا، فاحتفظ به خصوصيًا.

## تفاصيل الطابعة والملصق

- الجهاز `P2_3083`، ومفتاح TiMini الفعلي `toprint_hprt_esc_zl1` (الحرف **l** قبل 1، كما أكد `--list-models`).
- استُخرج ملف التعريف من إصدار CLI المثبت: 203 dpi، وعرض قابل للطباعة 384 نقطة، أي نحو 48.05 مم داخل ورق 50 مم.
- العربية والسعر وكود الصنف وCODE128 تُرسم في Chrome باستخدام Canvas قبل الإرسال؛ السعر لا يُختزل إلى عدد صحيح، وأصفار بداية الباركود محفوظة.
- الخطوط بعرض نقطتين مع منطقة بيضاء مناسبة حول الرمز؛ الباركود الذي لا يتسع يُرفض بدل تصغير خطوطه عشوائيًا. الاسم الطويل قد يختصر بصريًا في المعاينة، بينما قيمة الباركود لا تتغير.
- يُنشأ PDF مؤقت متعدد الصفحات: كل صفحة ملصق مستقل. تُحفظ هوامشه ويُعطل القص الآلي والتدرج، وتُضبط الفجوة البرمجية بين الصفحات على صفر. الملف المؤقت يُحذف بعد انتهاء العملية.
- الخدمة تسلسل الطلبات، وتقيدها إلى 100 ملصق لكل طلب و5 طلبات معلقة. تستخدم رمزًا ومواقع مسموحة محددة ولا تنفذ أوامر shell من المتصفح.
- عند انقطاع الاتصال أو فشل CLI قد يكون جزء من الملصقات طُبع؛ افحص الرول قبل إعادة الطلب. لا توجد إعادة إرسال تلقائية. منع تكرار المعرّف مؤقت طوال جلسة الخدمة، وليس ضمان طباعة مرة واحدة بعد إعادة التشغيل.
- نجاح CLI يعني انتهاء الإرسال حسب TiMini، وليس تأكيدًا ميكانيكيًا بخروج كل ملصق أو اعتماد جودة الباركود.

## اختبار القبول الفعلي

اطبع ملصق 50×60 واحدًا باسم عربي وسعر عشري وكود معروف، واقرأه بقارئ الباركود المستخدم في العمل. ثم اطبع 5 نسخ وتحقق من توقف كل نسخة عند الفاصل، ومن عدم فقد/تكرار الملصقات. اختبر بعد فصل وإعادة تشغيل الطابعة. لا تعتمد 50×20 أو 50×30 إلا بعد تركيب رول مناسب وتجربة المحاذاة وحساس الفجوة. ضبط أبعاد الصورة وحده لا يضمن دعم الميكانيكا للمقاس.

## نتيجة الاختبار على الجهاز الحالي

بتاريخ 27 أكتوبر 2026 نجح إرسال ملصق اختبار 50×60 مم من Chrome إلى P2_3083، وأكد المستخدم خروج الملصق كاملًا وواضحًا بالعربية والسعر والباركود. الإرسال الافتراضي (180 بايت/10 مللي ثانية) أدى في الاختبار الأول إلى إخراج جزئي رغم عودة CLI بنجاح؛ استُخدم بدلًا منه ملف تعريف محلي بحزم 96 بايت وفاصل 30 مللي ثانية، ونجح الاختبار المصحح. السجل أثبت نقل 23030 بايت خلال نحو 8 ثوانٍ. لا يثبت ذلك منفردًا أن سرعة النقل هي السبب الوحيد، ولا يغني عن اختبار قراءة الرمز بالقارئ الفعلي.

يولّد الإعداد `printer-config.local.json` بهذه القيم، ويسجل تشخيص آخر طلب في `last-print.local.log`. لا تُرفع هذه الملفات إلى Git. لم يُختبر بعد إخراج دفعة متتالية أو رول 50×20/50×30 على الجهاز؛ اعتمدها بعد اختبار القبول أعلاه.


في 28 أكتوبر 2026 تأكد ضبط P2 إلى 96 بايت/20 مللي ثانية بعد ظهور فواصل وحركة متقطعة مع 96/30. راجع دليل الإصدار 1.1.3 لنتائج المقارنة والترقية الآمنة للملفات القديمة.
