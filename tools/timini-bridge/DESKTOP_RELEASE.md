# توزيع أداة الطباعة على مستخدمي النسخة السحابية

المنتج: **HWNiX Print Bridge 1.1.3** — Windows 10/11 x64.
الموقع الافتراضي المسموح: **https://bill.hwnix.com**.

## حزمة المستخدم

الملف النهائي بعد البناء:

`tools/timini-bridge/release/HWNiX-Print-Bridge-Setup-1.1.3.exe`

يُنسخ أيضًا إلى `public/downloads/HWNiX-Print-Bridge-Setup-1.1.3.exe` لظهور زر التنزيل في واجهة الملصقات. ارفع هذا الملف مع الواجهة عند النشر. الحزمة غير موقعة بشهادة ناشر، وقد يظهر تحذير Windows عند تشغيلها؛ إصدارها باسم ناشر موثّق يحتاج شهادة توقيع خاصة بكم.

المستخدم يثبت ملفًا واحدًا، ويختار الطابعة من واجهة عربية، ويحفظ رابط الموقع، وينسخ رمز الربط إلى إعدادات الملصقات في الموقع. لا يحتاج Node.js أو Python أو نسخة من المشروع. يتوفر اختصار لسطح المكتب وقائمة ابدأ، وخيار تشغيل الأداة مع Windows، وإزالة من التطبيقات المثبتة.

## البنية

- `desktop/Launcher.cs`: مشغّل Windows وأيقونة بجوار الساعة، باستخدام C# و.NET Framework الموجود في Windows. يبدأ Node المضمّن ويتحكم في إغلاق الخدمة عندما لا توجد مهام نشطة.
- `desktop.mjs`: الخدمة المثبتة وواجهات الملفات والمحرر والإعداد داخل نافذة WebView2؛ تحفظ إعدادات المستخدم خارج مجلد التثبيت.
- `desktop-config.mjs`: اكتشاف الأجهزة وتحليل كتالوج الموديلات وتصدير إعداد TiMini الموافق للموديل المختار.
- `server.mjs`: طابور الطلبات وعزل المواقع ورمز الربط والطباعة عبر TiMini، مع بقاء مسار التطوير السابق متاحًا.
- `desktop/admin.*`: واجهة عربية للملفات وPDF والمحرر بخمسة صفوف، بلا اعتماد على CDN أو خطوط خارجية.
- `desktop/build-windows.ps1`: بناء حزمة مكتفية بالمكونات اللازمة باستخدام NSIS، مع التحقق من بصمات الملفات التنفيذية.

Node.js وTiMini مضمّنان داخل الحزمة بتراخيصهما. لا تُضمّن إعدادات المطوّر أو رموز الربط أو سجلاته. يُنشأ رمز طباعة جديد مستقل عند أول تشغيل على كل حساب Windows، ومفتاح إدارة منفصل لكل جلسة. الإعدادات محفوظة في `%LOCALAPPDATA%\HWNiXPrintBridge` وتبقى عند إزالة البرنامج.

الخدمة تقبل الطباعة من المواقع المحفوظة فقط وبرمز صحيح. إعدادات الإدارة ليست متاحة للموقع السحابي؛ تفتحها أيقونة الأداة بمفتاح جلسة محلي. يجب منح Chrome إذن الوصول المحلي على موقع الفواتير. فتح الموقع على لابتوب جديد يحتاج تثبيت الأداة وإعداد الطابعة هناك؛ إعداد جهاز لا يغيّر أجهزة المستخدمين الآخرين.

## حدود الدعم

الطابعة التي اختُبرت فعليًا هي P2_3083 بتعريف `toprint_hprt_esc_zl1` ومقاس 50×60 مم. يحفظ هذا التعريف ضبط النقل المؤكد في الإصدار 1.1.3: 96 بايت مع فاصل 20 مللي ثانية. باقي تعريفات TiMini تحتفظ بإعداداتها الأصلية؛ ظهور الموديل في القائمة يمثل دعم المحرك المعلن، ولا يمثل اختبارًا ماديًا له في HWNiX.

تُستخرج أبعاد الرسم وخيارات الورق من تعريف الطابعة المختارة، بما فيها خيارات الورق التي تختلف في العرض. طول الملصق يمكن اختياره من 20 و30 و60 مم. يجب ملاءمة الرول وحساس الفجوة، واختبار المحاذاة وقراءة الباركود بالقارئ الحقيقي. الأجهزة التي لا يدعمها TiMini تحتاج محولًا جديدًا أو تعريف Windows؛ خيار «طباعة المتصفح» يبقى متاحًا ولا يحتاج أداة HWNiX.

انتهاء الإرسال حسب CLI لا يضمن خروج الورق في البروتوكولات التي لا تؤكد اكتمال الطباعة. لا تعاد مهام الطباعة تلقائيًا بعد انقطاع غير واضح. الرموز المكررة تُمنع خلال جلسة الخدمة، وليس بعد إعادة تشغيلها.

## بناء الإصدار على Windows

```powershell
npm run printer:package
```

المرة الأولى تحتاج إنترنت لتنزيل ملفات البناء الرسمية. يمكن تمرير `-NodePath` و`-TiMiniPath` و`-NsisPath` لنسخ محلية مطابقة للإصدارات المثبتة ببصماتها في سكربت البناء. أعد بناء المثبّت عند تحديث Node أو TiMini، وحدّث الإصدار والبصمات والتراخيص معًا. لم يُضف تنزيل تحديثات وتنفيذها تلقائيًا على أجهزة العملاء.

لبناء الواجهة ونشرها بعد تجهيز المثبّت:

```powershell
npm run build
```

احتفظ بملف التثبيت وبصمته من مجلد `release` كأثر إصدار. مخرجات البناء والملفات التنفيذية محلية ومهملة من Git؛ في CI ابنِ المثبّت على Windows وانقل مخرجاته إلى `public/downloads` قبل بناء/رفع الواجهة، أو انشره في استضافة ملفات ثم عدّل رابط التنزيل.

## اختبارات المطوّر

```powershell
npm run test:printer
npm test -- tests/unit/print/labelData.test.js
```

يجب أيضًا اختبار التثبيت والإزالة وإعادة التثبيت، وظهور شاشة الإعداد، وحفظها، والعمل من نسخة مثبتة دون Node في PATH. اختبار المخدمات الآلي لا يغني عن تجربة الورق الفعلية لكل موديل تدعمه رسميًا.


## الجديد في 1.1

الواجهة داخل نافذة Windows باستخدام WebView2، ولا تفتح المتصفح للإعداد. يبقى عنوان loopback للاتصال الداخلي فقط. يتكفل المثبت بتجهيز WebView2 من Microsoft عند غيابه؛ يحتاج الإنترنت في هذه الحالة.

يدعم اختيار عدة ملفات PDF أو PNG/JPEG/GIF/BMP، ومعاينة صفحات PDF، والنسخ والصفحات والسواد وتحويل الصورة. محرر الملصقات يضم أربعة صفوف نصية وصفًا خامسًا يتحول بين QR وCODE128، مع تفعيل مستقل وحجم خط ومحاذاة ومعاينة مباشرة وحفظ قالب محلي. الملفات مؤقتة في الذاكرة؛ القالب والإعدادات فقط تبقى على القرص.

في الموقع توجد أربعة مسارات: طباعة المتصفح، إرسال إلى HWNiX للمعاينة، طباعة مباشرة عبر HWNiX، وتنزيل PDF. مسار المعاينة يفتح نافذة الأداة وينتظر ضغط المستخدم على طباعة. مسار الطباعة المباشرة يبقى في الخلفية. تم إصلاح تحميل jsPDF في Vite باستخدام استيراد ثابت وإدراجه في optimizeDeps.

يسجل المثبت رابط hwnixprint://open وفتح باستخدام للأنواع المدعومة واختصار إرسال إلى في Windows، دون تغيير التطبيقات الافتراضية. لا يسجل Share Target عامًا؛ ظهور البرنامج داخل قائمة مشاركة كل متصفح يحتاج دعمًا وتغليفًا مختلفين ولا يدخل في هذا الإصدار.

للتطوير المحلي أضف http://localhost:5173 في المواقع المسموحة داخل الأداة. للإنتاج يكفي https://bill.hwnix.com. بعد تحديث واجهة التطوير استخدم Ctrl+F5؛ لا تحتاج حذف إعدادات الطابعة.

المكونات الإضافية: WebView2 SDK 1.0.4314.35، PDF.js 6.4.299، QRCode 1.5.4، مع مكتبات المشروع jsPDF وJsBarcode. يجمع build-ui.mjs الواجهة للاستخدام دون CDN، ويضم تراخيص المكونات. يمكن تمرير -WebViewSdkDirectory و-WebViewBootstrapper إلى البناء، إضافة إلى مسارات Node/TiMini/NSIS.

التحقق لهذا الإصدار: 13 اختبار خدمة، وبناء واجهة الإنتاج، ونافذة WebView2 فعلية ببيانات معزولة، وحفظ/استعادة القالب، واستيراد PDF وصورة والتنقل بين الصفحات، وقراءة QR وCODE128 بقارئ برمجي، وتوليد PDF عربي وإرساله من كود الموقع في Chrome للمعاينة. لم يُرسل اختبار طباعة فعلي جديد لهذا الإصدار. يبقى اختبار ورقة فعلية مطلوبًا لدى المستخدم.

## التحقق من الطابعة في 1.1.1

قبل حفظ إعداد جديد وقبل كل مهمة في الطابور، تفحص الأداة حالة راديو Bluetooth في Windows ثم تبحث عن الجهاز. الاسم المكتوب يجب أن يطابق الاسم المعلن؛ يحفظ البرنامج عنوان Bluetooth الفعلي والاسم للعرض، ويرفض الاسم غير الموجود أو المكرر دون إفساد الإعداد السابق. تتوفر أيضًا أداة فحص للطابعة المحفوظة داخل نافذة الإعداد.

Bluetooth المغلق أو المعطل، وغياب الجهاز، وانتهاء مهلة البحث، وانشغال الاتصال أو انقطاعه، لها رسائل عربية. الفشل أثناء الفحص يمنع تشغيل أمر الطباعة. الفشل بعد بدء الإرسال يوضح احتمال خروج جزء من الورق، ولا يعيد الطلب تلقائيًا. يعاد الفحص عند تنفيذ كل مهمة وليس عند بدء الخدمة فقط، وتبقى رموز حالة API متوافقة مع الواجهة السابقة مع حقل phase إضافي.

البحث وحده لا يثبت أن الطابعة تعمل أو أن الورق والبطارية متاحان؛ قد يعيد Windows جهازًا مقترنًا من الذاكرة. لذلك يبقى فشل الاتصال الفعلي معالجًا أيضًا، ولا تعرض الواجهة ادعاء «جاهزة للطباعة» اعتمادًا على وجود الخدمة أو نتيجة البحث فقط. إذا تعذر قراءة API الراديو يُستخدم بحث الجهاز الفعلي دون الادعاء بأن Bluetooth مغلق.

الاختبار: نجحت 20 حالة آلية للخدمة، وقراءة حالة Bluetooth الفعلية على Windows، واختبار النافذة مع هدف غير موجود وفحص TiMini حقيقي. لم يُنفذ أمر طباعة فعلي، وأثبت الاختبار رفض الاسم الوصفي مع بقاء الإعداد السابق.
## 1.1.2 — إدارة الطابعات ونافذة العمل

إضافة قائمة الطابعة فوق المعاينة والمحرر، وحوار إضافة جهاز من البحث واختيار الموديل. تحفظ الأداة حتى 20 طابعة بعنوان Bluetooth الفعلي مع ملف تعريف وأبعاد وورق مستقل لكل جهاز. الطابعة المختارة هي افتراضية طلبات الموقع الجديدة، وكل مهمة تأخذ نسخة من إعداد طابعتها وقت قبولها. لا يسمح بتغيير الطابعة الافتراضية أثناء وجود طباعة جارية.

لا يستخدم العنوان المحفوظ فشل بحث الإعلان كسبب لمنع الطباعة؛ يفحص Bluetooth ثم يترك لمحرك TiMini فتح الاتصال الفعلي. الأسماء القديمة تحتاج إلى إعادة اختيار الجهاز الصحيح من البحث، ولا تُحوّل تلقائيًا إلى جهاز آخر تخمينًا.

تخطيط النافذة ثابت بأشرطة أدوات وتبويبات وحاويات ذات تمرير داخلي عند الحاجة. اختيار صف المحرر يلغي الحاجة لعرض حقول الصفوف الخمسة في صفحة طويلة. تم اختبار النافذة الفعلية عند 1260×800 و1000×650 والتحقق من ظهور أزرار الطباعة والاختيار والمعاينة دون تمرير المستند.

نجحت 25 حالة اختبار للخدمة والطوابير والملفات وهويات الطابعات وتعددها وحفظ الاختيار بعد إعادة التشغيل. نجح اختبار واجهة WebView2 بإضافة وتبديل طابعات ذات أبعاد مختلفة وتسجيل وجهة كل مهمة بمحرك وهمي. لم يُرسل اختبار ورق جديد أثناء التطوير. إعداد الطابعة المحلية الحالية صُحح من الاسم الوصفي إلى عنوان P2_3083 المؤكد من Windows وTiMini، دون تعديل رمز ربط الموقع.
## 1.1.3 — جودة P2 والنوافذ المنبثقة (28 أكتوبر 2026)

الصورة الأصلية تُرسل كـBW1 دون تنقيط. إعداد 96/30 السابق أكمل الورق لكنه ظهر بحركة متقطعة وفواصل أفقية. اختُبر نفس PDF/الصفحة الأولى دون تغيير الباركود أو السواد: 180/10 أرسل خلال نحو 1.5 ثانية وخرج جزئيًا؛ 96/10 أرسل خلال 2.8 ثانية وخرج جزئيًا؛ 96/20 أرسل خلال نحو 5.2 ثانية، وأكد المستخدم خروج الملصق كاملًا وواضحًا بلا فواصل وبحركة سلسة. هذا تحقق على P2_3083 الحالية، وليس ضمانًا عامًا لكل أجهزة السوق.

أصبح P2_STREAM = 96 بايت/20 مللي ثانية. preparePrinter يستخدمه لتعريف toprint_hprt_esc_zl1 فقط. عند بدء الخدمة، تُرقّى الوصفة القديمة المطابقة تمامًا لـ96/30 فقط داخل ملفات printer-*.json التي ولّدتها الأداة في مجلد بيانات المستخدم. تحفظ الإعدادات المخصصة والمسارات الخارجية والموديلات الأخرى كما هي. لا يتغير رمز الربط. تم تطبيق الضبط المؤكد على ملف الطابعة الفعلي أيضًا.

أخطاء الاتصال والتحقق ونتائج البحث الخالية تظهر كـdialog داخل النافذة، مع عنوان واضح ونص عربي وموافق وEsc. الرسائل المتزامنة تُعرض بترتيبها، وتظهر فوق حوار إضافة الطابعة عند الحاجة دون إغلاقه. النص يُعرض عبر textContent؛ تبقى رسائل التقدم والنجاح في شريط الحالة دون مقاطعة.

نجحت 28 حالة اختبار آلية، واختبار WebView2 الفعلي للنوافذ المنبثقة والفشل وعدم وجود أجهزة والتركيز والإغلاق الآمن وعرض النص دون HTML. لا تُرسل أي عينة جديدة تلقائيًا بعد خطأ، ولا يُعد نجاح CLI تأكيدًا ميكانيكيًا بخروج الورق.

مقارنة إضافية لوضوح النص: أُعيدت محاكاة عتبة TiMini المتغيرة (متوسط الرمادي ناقص 13)، فتطابق عدد البكسلات السوداء 12106 مع سجل المحرك. جُرّب تغليف بديل يحافظ على 9147 بكسل أسود من الصورة الأصلية دون التحجيم؛ أكد المستخدم أن الورقة لم تتحسن وأصبحت أسوأ. رُفض هذا التعديل وأُعيدت ملفات الموقع والمحرر وبناء الواجهة إلى المسار السابق. يبقى 96/20 فقط ضبط النقل المعتمد، ومستوى الكثافة الحرارية والوضوح يحتاجان متابعة بالصور.

## 1.1.4 — P2 calibration and reliable connection drain

- P2 jobs use a separate frozen Python worker built from TiMini v0.9 sources; the original CLI remains for setup, scanning and other printer models.
- Native Windows RFCOMM resolves the SPP service UUID instead of assuming a channel. After sending, the same connection remains open for 12 seconds. This is a passive drain allowance, not printer ACK or proof of paper completion. No automatic retry.
- Physical calibration at 96 bytes/20 ms and darkness 3 printed completely, including both barcodes and the final solid black strip. The user confirmed the large text was clear and the strip uniform. The original CLI route could truncate that calibration.
- Website labels use larger Tahoma glyphs and readable captions. CODE128 uses integer 3-dot modules when they fit with quiet zones, otherwise 2-dot modules. Physical PDF dimensions remain unchanged; the earlier rejected pixel-aligned PDF experiment remains reverted.
- The 1.1.3 popup errors and printer selection remain included. Customer Python installation is unnecessary.
- Build the worker using desktop/worker/build-worker.ps1, then pass its executable via -P2WorkerPath to desktop/build-windows.ps1. Worker source, build notes and license provenance are in desktop/worker.
