# فلاتر المتجر على جميع الشاشات

التصنيفات والبراندات تدعم التحديد المتعدد، ويحدث النقر النتائج تلقائيًا دون زر تطبيق مخفي. اختيار عدة تصنيفات يجمع نتائجها، واختيار عدة براندات يجمع نتائجها، ويجمع النوعان مع نطاق السعر والبحث والمخزون بالشروط المشتركة.

- الاختيار الثاني يضاف للأول؛ النقر على المحدد مرة أخرى يزيله. تظهر حالة التحديد فورًا، ويمكن إزالة كل اختيار من شريحته أو مسح الجميع.
- السعر يحدث بعد350ms من آخر إدخال؛ القيم السالبة أو نطاق أعلى أقل من الأدنى تعرض خطأ محليًا بدل إرسال طلب غير صالح.
- لوحة الهاتف والتابلت تبقى مفتوحة عند تحديث الفلاتر، وبها قائمة قابلة للتمرير وزر «عرض النتائج» ثابت لإغلاق اللوحة، لا لتطبيق الاختيارات. التنقل إلى صفحة أخرى يغلقها كالسابق.
- يعامل /store/ و/store كصفحة واحدة عند تغيير الفلاتر، لدعم إعادة التوجيه التي تنفذها الاستضافة للمجلدات؛ يوجد اختبار متصفح مستقل لهذا المسار.
- تحفظ الفلاتر في الرابط وتستعاد بعد تحديث الصفحة، بما فيها البراندات والسعر والمخزون والترتيب. روابط category_id وbrand_id القديمة مقبولة. القائمة الجديدة ترسل category_ids[] وbrand_ids[] إلى API؛ يتطلب نشر الباك إند الداعم أولًا.
- كل تغيير يعيد الترقيم إلى الصفحة الأولى. استجابة طلب قديم لا تستبدل نتائج الاختيار الأحدث.

اختبارات الوحدة تتحقق من التوافق القديم وتحويل الرابط وحفظ القوائم وعدم مشاركة مصفوفة مسودة الاختيار، والترقيم والتزامن. اختبارات Playwright تفحص360 و390 و768 و959 و960 و1440px، واختيار تصنيفين وبراندين معًا والتحديث وإزالة أحدها ومسح الجميع والسعر. تستخدم ردود API محاكية، ولا تنفذ عمليات كتابة أو اختبارات حمل على أي خادم.

Workflow staging يبني الحزمة ثم يشغل اختبارات الفلاتر والتنقل على preview محلي في runner قبل رفع dist. يبقى main وWorkflow الإنتاج دون تغيير؛ التراجع المنسق يعيد إصدار الفرونت السابق إذا أعيد الباك إند القديم.
