# تجربة الفاتورة على الهاتف

النسخة الأولى تعيد تنظيم الإنشاء والتعديل على شاشات أقل من 600 بكسل، مع استخدام بيانات الفاتورة ودوال الحساب والحفظ الحالية. شاشة الكمبيوتر تحتفظ بالجدول.

## التجربة اليدوية

- افتح إنشاء فاتورة من الهاتف: راجع بيانات العميل والمخزن ونوع الفاتورة من بطاقة البيانات.
- أضف منتجًا بالاسم أو الباركود، ثم غيّر الكمية والوحدة والسعر والخصم قبل الإضافة.
- أضف المنتج مرة ثانية، ثم جرّب تعديل كميته ووحدته بعد الإضافة وحذفه.
- افتح خيارات الحسابات، وجرّب الخصم والضريبة والرصيد السابق والمدفوع والخزنة.
- جرّب حفظ فاتورة جديدة، ثم افتح فاتورة موجودة وعدّلها.
- راجع البيع والشراء والمرتجعات والتقسيط؛ تأكيد خطة التقسيط يظل جزءًا من مسار الحفظ الحالي.
- افتح لوحة مفاتيح الهاتف وتأكد من الوصول للحقول والإجراءات؛ اختبر الرجوع من شاشة إضافة الصنف.
- راجع الكمبيوتر والتابلت بعد تجربة الهاتف.

سجّل ملاحظاتك بالصفحة والإجراء والنتيجة المتوقعة، مع مقاس الشاشة إن أمكن.

## التحقق الآلي المعزول

```powershell
node node_modules/@playwright/test/cli.js test --config playwright.invoice-phone.config.js
```

الاختبارات تركّب مكوّن الفاتورة الحقيقي ببيانات API تجريبية عبر Axios adapter، وتفحص بيانات الحفظ دون الاتصال بقاعدة البيانات. صفحة الاختبار مقيدة بالمضيف المحلي والمنفذ 5176، ولا تدخل في بناء التطبيق المنشور. الاختبارات لا تستبدل تجربة لوحة مفاتيح أندرويد الفعلية أو التحقق من الخادم ببيانات العمل.

المعاينات في `docs/mobile-invoice-preview/` من بيئة الاختبار.
