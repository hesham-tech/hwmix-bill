# حالة تنفيذ خطة إنتاج المتجر
آخر تحديث: 5 نوفمبر 2026. **اكتملت مراجعة وإصلاحات النسخة المحلية ضمن النطاق الحالي واختباراتها؛ لم يُعتمد فتح الإنتاج.**
الخطة المرجعية: [store-production-readiness-plan.md](store-production-readiness-plan.md). دليل المرحلة الثانية: [store-production-activation.md](store-production-activation.md). التقسيم مرحلتان فقط.

## المرحلة الأولى — المنفذ
- صفحة /app/store-operations ورابط «المتجر الإلكتروني ← إدارة المتجر» في أول مجموعة بالقائمة الجانبية. عولج خطؤها الناشئ عن غياب جدول store_settings، واختُبر الرابط والتبويبات والصلاحيات وحالة فشل الاتصال وإعادة المحاولة.
- حساب إلزامي عند الشراء وتوثيق البريد وعناوين وطلبات مرتبطة بالمستخدم، دون كشف طلبات حساب آخر برقم الهاتف أو برمز وصول قديم. التصفح والسلة متاحان للزائر.
- عرض سعر من الخادم، تثبيت الأسعار والضرائب والسياسات والعمولة ووحدات البيع والعناوين، هوية محاولة شراء ثابتة، وحجز المخزون وإلغاؤه أو استهلاكه مرة واحدة. تعديل أسعار الشحن لا يعدّل طلبًا سبق اعتماده.
- فلاتر السعر والماركة والبائع وترتيب السعر الفعلي وحدود الترقيم. الكتالوج يعتمد مخزن التجهيز وحالة الدفعة والصلاحية ووحدة البيع. /store/cart/validate مربوط. يحمي المتجر نتائج البحث من الاستجابات القديمة، ويطلب اختيار الخيارات للمنتج متعدد الخيارات قبل إضافته.
- حساب مستقل للبائع ودفتر قيود وحجوزات وتمويل وصرف، منفصل عن خزائن ERP. سياسة عالمية ← باقة ديناميكية موثوقة ← استثناء شركة، مع احترام الصفر وfalse وnull، وتثبيت القاعدة مع الطلب ومراجعتها عند تغيير الباقة.
- شحن يدوي لكل بائع وعنوان استلامه، مع ناقل إدارة احتياطي. سعر لكل محافظة واستثناء بائع أعلى من السعر العام، وتعطيل المسار أو COD دون تسرب إلى العام. تكلفة الناقل مستقلة عن رسم العميل؛ الاستثناء المخفض يرث تكلفة الناقل العامة إن لم تُدخل تكلفة صريحة. لا شحن مجاني افتراضي لمحافظة جديدة.
- جلسات ومحاولات دفع محفوظة وإعداد حساب مشفر ثابت، تحقق موثوق من المزود والمبلغ والعملة والبيئة والمرجع، Webhook موقع، منع إعادة احتساب الالتقاط وإعادة المحاولة، واسترداد بمرجع التنفيذ الحقيقي. موصلات Stripe وPaymob وKashier قابلة للاختبار؛ صلاحية الحساب التجاري لم تُثبت ببيانات حقيقية.
- تسوية دفعات البوابة مع البنك ورسومها وضريبتها ومرجعها وعدم تكرار إثبات التحويل. استرداد بوابة بعد تسوية سابقة يولد تسوية سالبة؛ استرداد بنكي يدوي لا يُخصم خطأً من مستحق البوابة.
- مرتجعات جزئية مع فحص واستعادة الجيد دون التالف، وحساب تراكمي للضريبة والشحن والعمولة والتكلفة، واستردادات ومطابقة ERP. تعذر التسليم/RTO لا يحرر المخزون قبل الاستلام والفحص، ولا ينشئ استرداد COD غير محصل، ويسجل التكلفة والجهة المتحملة.
- فواتير متجر مُدارة لا تحرك خزينة ERP أو مديونية العميل كبيع عادي، مع منع تعديلها من مسارات الفواتير العامة. تكلفة المخزون المجهولة تمنع تأكيد الخروج بدل اختلاق تكلفة صفرية.
- outbox دائم ومشغل محدود الزمن ودفعات عادلة واسترداد leases، ووضع sync للاستضافة المشتركة وasync مع worker حقيقي للـVPS. نبض المجدول والعامل وتأخره يراقبان قبول الطلبات في الإنتاج.
- أحداث المتجر موصولة بأتمتة وقوالب وحدة الإشعارات والبريد المشترك. اختُبرت ملكية القالب والتأخير والتكرار وترميز HTML وتغيير البريد ورمز التوثيق. لا WhatsApp/SMS آلي للمتجر عند الإطلاق.
- تنظيف SVG قبل الحفظ وإزالة المراجع الخارجية وقيود صور الشركة والكيان. تحديث Laravel/Vue/Vite والتبعيات ذات الصلة؛ تدقيق Composer بعد تحديث Symfony YAML إلى 7.4.23 بلا تنبيهات.
- ترحيلات 1–15 مطبقة **محليًا فقط**. الترحيل 13 أصلح أنواع محاسبة MySQL وسمح بفاعل NULL لمستند النظام، و14 أضاف استثناءات الشحن؛ أُصلح ترتيب الفهارس ليتوافق مع FK في MySQL وليقبل إعادة المحاولة بعد تنفيذ جزئي. الترحيل 15 أضاف فهرس مسح تذكيرات الفواتير.
- إشعارات ERP المجدولة تمر عبر outbox محدود وعادل، وتعيد فحص الاستحقاق عند الإرسال، مع تدارك سبعة أيام منذ التفعيل ومنع التكرار. عُزل SMTP الخاص بالشركات، وقُيد WhatsApp المجدول بالمراجعة اليدوية حتى موافقة المستلم والقالب المعتمد؛ لا إصدار Graph API قديم ثابت.
- واجهات ERP تعرض فواتير المتجر للقراءة وتخفي الإجراءات والأرصدة الخاصة بالعميل، مع منع التعديل في الخادم. اختبار المرتجع يغطي طلب العميل واعتماد الإدارة والفحص دون الادعاء باكتمال الاسترداد قبل حدوثه.
- إعادة التسعير تتم بإعادة بناء سلة من طلب ملغى بأسعار ومخزون حاليين، ثم عرض سعر وموافقة جديدين؛ لا تغيير صامت لطلب مدفوع أو حساباته أو استرداده السابق.
- أمر قراءة فقط: php artisan store:readiness --launch يفحص الإعدادات والترحيلات ومتطلبات الإطلاق ويعرض العوائق، ولا يشغّل الشراء أو المجدول أو البريد.

## حدود النسخة المحلية والمتابعة
- أُغلقت مراجعات إعادة التسعير وإشعارات ERP والمرتجعات وفواتير ERP ومكتبة الصور بالأدلة المذكورة أعلاه. تبقى النتائج مقيدة بنطاق الاختبارات وبيئاتها.
- بتاريخ 4 نوفمبر طلب المستخدم تأجيل الدفع الحقيقي ومواصلة بقية العمل. لا اختيار مزود أو مفاتيح حقيقية مطلوب لاستكمال التطوير؛ التفعيل التجاري منفصل.
- آخر فحص قراءة فقط للجاهزية: %TEMP%/hwnix-final-readiness.json؛ ready=false لأن البيئة محلية والمتجر مغلق وتبقى إعدادات قانونية وضريبية ومرتجعات وبائعين ونبض Cron. لا يُفتح المتجر أو تُدخل قيم افتراضية لإخفاء هذه العوائق. خيار --launch ما زال يفحص معيار الإطلاق السابق الذي يتضمن البطاقات؛ تأجيل الدفع الحقيقي لا يعني طلب فتح COD منفردًا الآن.
- موصلات الدفع المنفذة حاليًا: Paymob وKashier وStripe. XPay ليس موصلًا منفذًا بعد؛ أي اقتراح بإضافته لا يُعد إثباتًا لتنفيذه أو توافق بروتوكول حسابه.
- لا موصل شحن API حقيقي ولا تحويل مصرفي آلي بمزود غير مختار. الشحن اليدوي والصرف المعتمد يدويًا هما المساران الحاليان المتفق عليهما.

## استكمال 5 نوفمبر — إصلاحات ومراجعة الإصدار
- تشخيص تمويل الشركاء أثبت نقصًا فعليًا في إنشاء financial_operations وربط القيود وتحديث رصيد العلاقة، وغياب دالة العكس المشار إليها بالمسار. أُكمل التسجيل الذري وربط الحركة والقيود والرصيد بالعملية، والعكس عبر المحرك المالي نفسه، مع قفل العملية الأصلية ومنع عكس المعاملات القديمة التي لا تملك مرجعًا موثوقًا. لا إصلاح تلقائي للبيانات القديمة أو اختلاق عمليات سابقة.
